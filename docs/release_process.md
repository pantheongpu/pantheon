# Release Process

This private repository publishes binary-only Pantheon releases through GitHub Releases. Public downloads must not include Python source, kernel C++ source, or source repository archives.

Official Linux binaries are compiled in the `quay.io/pypa/manylinux_2_28_x86_64` container. Packaging still runs on Ubuntu 22.04, while artifact verification rejects the launcher or any embedded ELF library requiring GLIBC newer than 2.28.

## Release Outputs

Each official release provides:

- `pantheongpu_<version>_amd64.deb`, generated by `packaging/build_deb.sh`.
- `pantheongpu_<version>_amd64.tar.gz`, a binary distribution bundle.
- `pantheongpu_<version>_amd64.zip`, a binary distribution bundle.
- `SHA256SUMS`, generated by the release workflow for download verification.
- Release notes generated automatically by GitHub.

The tar/zip artifacts are not source archives. They include the Debian package, standalone binaries, `INSTALL.md`, release notes, license, and install instructions for Ubuntu/Debian, RHEL-family systems, and generic Linux.

## Debian Package Layout

The package installs:

```text
/usr/bin/pantheon
/opt/pantheongpu/bin/pantheon
/opt/pantheongpu/VERSION
/opt/pantheongpu/share/doc/pantheongpu/
```

The `/usr/bin` commands are thin wrappers that pass user arguments through unchanged. They do not force `--platform cuda`; Pantheon keeps its normal automatic CUDA, ROCm/HIP, or mock detection.

## Local Binary Package Build

Install the release dependencies:

```bash
python3 -m venv pantheon_env
source pantheon_env/bin/activate
pip install -r requirements.txt
```

Build all binary release artifacts:

```bash
make release VERSION=1.0.19
```

This writes:

```text
dist/pantheongpu_1.0.19_amd64.deb
dist/pantheongpu_1.0.19_amd64.tar.gz
dist/pantheongpu_1.0.19_amd64.zip
```

To build the standalone binary directory directly:

```bash
./build_pantheon.sh
```

`build_pantheon.sh` does not create old-style archives by default. Use `PANTHEON_CREATE_ARCHIVES=1 ./build_pantheon.sh` only for local experiments; official releases use `packaging/build_portable_release.sh` to compile in the manylinux baseline before assembling the release bundle.

## Local Install Smoke Test

```bash
sudo apt install ./dist/pantheongpu_1.0.19_amd64.deb
pantheon --test baseline_metrics --duration 10
pantheon --test fp64_virus --duration 30 --gpu 0
sudo apt-get remove pantheongpu
```

## Official GitHub Release

1. Update `VERSION` to the new semantic version, such as `1.0.19`.
2. Commit and push that `VERSION` change to `main`.

That is the release trigger. The `Release` workflow runs whenever `VERSION` changes on `main`.

The workflow will:

- Read and validate `VERSION`.
- Stop if the matching GitHub Release already exists, or if the matching tag points at a different commit.
- Reuse a matching tag that points at the current commit when a previous run created the tag but failed before publishing the release.
- Check whether the website release token is available before creating tags or publishing artifacts.
- Run the unit tests.
- Build the MkDocs site in strict mode.
- Compile mock kernels.
- Run normal mock smoke tests.
- Build the binary-only Debian package and binary tar/zip distribution bundles.
- Verify the packaged executable and embedded native libraries require GLIBC 2.28 or older.
- Install the actual `.deb` in parallel on Ubuntu 20.04/22.04/24.04 and Debian 11/12.
- Install the portable binary bundle on Red Hat UBI 8/9/10, CentOS Stream 9/10, Rocky Linux 8/9/10, AlmaLinux 8/9/10, and Fedora 43/44.
- Run `pantheon --version`, `pantheon --help`, and a mock-mode benchmark inside every compatibility container.
- Block tag creation and GitHub Release publication until every Linux compatibility job passes.
- Generate `SHA256SUMS`.
- Create and push the release tag.
- Publish a GitHub Release with the `.deb`, `.tar.gz`, `.zip`, and `SHA256SUMS` attached.
- Trigger the `pantheongpu/pantheongpu_website` release workflow.

## Website Release Trigger

The release workflow sends a `repository_dispatch` event to `pantheongpu/pantheongpu_website` after the Pantheon GitHub Release is published when the website token is configured.

Configure this repository secret before releasing:

```text
PANTHEON_WEBSITE_RELEASE_TOKEN
```

When configured, the token must have access to `pantheongpu/pantheongpu_website` and permission to create repository dispatch events. The website repository should listen for:

```yaml
on:
  repository_dispatch:
    types: [pantheongpu_released]
```

The dispatch payload includes `version`, `tag`, `release_url`, `source_repo`, and `source_sha`.

## Verifying Downloads

After downloading release files, verify them with:

```bash
sha256sum -c SHA256SUMS
```

The `.deb`, `.tar.gz`, and `.zip` entries should report `OK`.
